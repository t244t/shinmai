# 新米販売管理

新米の予約・店舗への配布と販売・精米予定・準備タスクをスマホで管理するアプリです。

- 画面：GitHub Pages（`index.html`）
- データ：Googleスプレッドシート「新米販売管理」
- つなぎ：Google Apps Script（`Code.gs`、GET + JSONP）

## セットアップ

### 1. スプレッドシートに GAS を入れる
1. Googleドライブで「新米販売管理」スプレッドシートを開く
2. 「拡張機能」→「Apps Script」
3. 最初からある `コード.gs` の中身を消して、このリポジトリの `Code.gs` を貼り付けて保存
4. 上の関数選択で `setup` を選び「実行」（初回は権限の確認が出るので許可）
   - 足りないシートや列を自動で作り、スプレッドシートの時間帯を東京に合わせます
   - 既存のデータは消しません

### 2. ウェブアプリとして公開
1. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
2. 実行ユーザー：**自分**／アクセスできるユーザー：**全員**
3. 表示された `/exec` で終わるURLをコピー

### 3. アプリにURLを入れる
- `https://t244t.github.io/shinmai/` を開き、⚙設定に URL を貼って「保存して読み込む」
- 端末ごとに保存されます。全員で同じURLを使うなら `index.html` の `DEFAULT_GAS_URL` に書いても構いません

### 4. GitHub Pages を有効にする
リポジトリの Settings → Pages → Branch を `main` / `(root)` にして Save

## 店舗間の移動（店舗タブ）
- 区分「店舗間の移動」で、選んだ店舗（移動元）から移動先へ動いた5kg・2kgの数を記録
- 店舗実績には移動元に「移動出」、移動先に「移動入」の2行が同じ番号の組で入る。取消は2行いっしょ
- 残＝配布＋移動（入−出）−販売−返品。販売率も移動を含めた入荷数で計算

## 出荷表の写真から取り込む（店舗タブ）
- 伊都国即売会の出荷表を撮影すると、日付・回目と出荷先ごとの5kg・2kgの数を読み取り、確認画面で直してから「配布」として記録
- 出荷先の列（マリナ・笹丘・ねぎぼうず・唐泊・本店・売店など）はアプリの店舗に自動で割り当て。変えた割り当ては次回から自動
- 写真はドライブの「新米_出荷表」フォルダに保存し、記録の備考にリンクを残す
- 同じ日・同じ回目の出荷表は二重に記録しない
- 準備：Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」に `GEMINI_API_KEY`（Gemini APIキー）を追加。モデルを変えるときは `GEMINI_MODEL`（既定 `gemini-flash-lite-latest`。速さ優先、失敗時は `gemini-flash-latest` で読み直し）

## 売上CSVの取り込み（店舗タブ）
- 直売所システムや各店舗のレジから出した売上CSVを選ぶと、新米5kg・2kgの販売数を店舗ごとに記録します（UTF-8・Shift_JIS どちらも可）
- 列（商品名・商品コード・数量・店舗・日付）は見出しから自動で推測。一度選んだ形式は端末が覚えます
- 新米の判定：商品コードが設定のJAN（価格入りなら先頭8桁）と一致する行、または商品名に「5kg」「2kg」がある行
- 店舗の割り当て：CSVの店舗名をアプリの店舗に結び付け（例：伊都国即売会→即売会本店、イオンスタイル笹丘→イオン笹丘）。「取り込まない」「＋店舗に追加」も選べ、決めた割り当ては次回から自動
- 日付が「1900/01/01」などのダミーのとき（期間の集計CSV）は、画面で選んだ計上日で記録。期間が重ならないように取り込む
- 数量がマイナスの行や、区分に「返品・取消」とある行は返品として記録
- 同じCSVを同じ計上日でもう一度取り込んでも二重にはなりません

## 精米日のカード（精米タブ）
作業の順に3段。今やる段だけ開き、終わった段は✓と要約になる（段の見出しを押すと開閉）
1. ① 依頼（持ち込む前）：使う玄米・玄米の袋数と端数・袋詰めしてほしい数・予備の袋 → 保存・🖨 依頼書
2. ② 持込：持込日・受取予定・精米代の目安 →「✅ 持ち込んだ」で持込済にして保存
3. ③ 精米後：「✅ 精米が終わった」で精米済にし、依頼の数が入った実績の欄を直して「実績を保存」・🏷 シール
- 備考・状態の手直し・📅 精米日の変更は「その他」にまとめた

## 玄米（もみすり）と検査（精米タブ）
- もみすりごとに玄米（30kg袋数＋端数kg）とくず米kgを記録。ロット番号（G001〜）を自動で付ける
- くず米の割合＝くず÷（玄米＋くず）。玄米の残り＝玄米の合計−精米に持ち込んだ玄米（持込済・精米済）
- 等級検査は毎週 月・金。記録時に次の検査日を入れ、結果が出たら等級（一等・二等・三等・規格外）を選ぶ。検査前の日はカレンダーに「🔍検査」
- 精米の回で「使う玄米」を選ぶと、ロットごとの残りが分かる。検査前の玄米で表示シールを開くと、確認文言（検査証明）の注意を表示

## 持込・予備の袋・精米日の変更（精米タブ）
- 持込日（実際に持ち込んだ日）と受取予定（例：午後）を記録。カレンダーの「持込」は持込日に出る
- 予備の袋：依頼の袋数に足して渡す袋を種類ごとに記録（「予備を＋3にする」で設定の枚数を一度に入れる）。持込済の間は在庫から予備も引き、精米済で返ってきた扱い
- 「📅 精米日を変更」で精米所の都合に合わせて日を移す（持ち込み済みなら持込日はそのまま）
- 精米代の目安＝玄米kg×精米単価（設定、初期30円/kg）。支払額の欄に薄く表示

## 精米加工依頼書のレイアウト
- 農・みのり用：持込日・精米日・お渡し／①お預けする玄米（30kg袋・端数・合計）／②袋詰めのお願い（袋詰め数・重さ・お渡しした袋（予備を含む））／注記・受付欄
- A4横に2枚分（左＝精米所様用、右＝農・みのり控え）

## 依頼と実績（精米タブ）
- 精米日ごとの袋数は「依頼の数」。精米加工依頼書はいつもこの数で印刷する
- 状態を「精米済」にすると「精米の実績」欄が開く。初期値は依頼の数なので、違う所だけ直して保存（米袋・無地袋の5kg・2kg、残った端数kg）
- 依頼との差を表示し、差がある精米日はカレンダーに「依頼と差」の印
- 袋・シールの在庫、表示シールの枚数は、実績があれば実績の数を使う

## 袋・シールの在庫（精米タブ）
- 米袋5kg・無地袋5kg・米袋2kg・無地袋2kg・新米シール の5種類を管理
- 新米シールは袋1枚に1枚として、その回の袋の合計枚数を引く
- 在庫 ＝ 最後の棚卸の枚数 ＋ その後の入庫 − 持ち込んだ袋
- 精米日の状態を「持込済」か「精米済」にすると、その回の袋数が在庫から引かれる（袋は持込日に手元から出るため）
- 「予定」の精米日の袋数を合計して、予定後の残りを表示。足りなくなる精米日をホームと精米タブで警告
- 棚卸は「その日の作業が終わった後に数えた枚数」。ずれたら棚卸を入れ直せば合う
- 初めて使うときは、今ある枚数を種類ごとに「棚卸」で入れる

## 印刷（依頼書・表示シール）
- 精米タブの各精米日にある「🖨 依頼書」「🏷 シール」からプレビューを開き、右上の「印刷」
- 依頼書：A4横に2枚分（1枚は控え）。依頼日は持込日（精米日の前日）が初期値
- 表示シール：「精米表示シール_A4各種」と同じ9パターン（2面・4面・6面・8面・10面・12面・18面・21面・24面、すべてA4余白なし）＋カスタム寸法
  - 記載内容：名称／原料玄米（原料区分・産地・品種・産年・使用割合・確認文言①②）／内容量／精米時期（上旬・中旬・下旬）／販売者
  - 内容は⚙設定の「表示シール」で変更。確認文言や割合は空欄にすると表示されません
  - 用紙代の目安（18面の1面単価から計算）を表示
  - バーコード欄：シールの右側にJANコード（EAN-13）を縦向きで印刷。用紙ごとにON/OFF（10面は初期ON）、倍率80〜100%
    - JANコードは⚙設定の「JANコード 5kg／2kg」に入力（12桁ならチェック数字を自動計算）。未設定の規格は空欄で印刷
    - バーコードの方式：「固定」＝番号どおり（2始まりのインストアコードはチェック数字を付け直す）／「価格入り」＝先頭8桁＋税込価格4桁＋チェック数字
  - 枚数は精米タブの袋数が初期値。途中まで使った用紙は「開始位置」で続きから印刷
  - 文字の大きさはシールに合わせて自動調整。8ポイント未満になると警告
  - シールの端から「内側の余白」（10面などの大きいシールは3mm、小さいシールは1.5mm）を空けて印刷。はみ出すときは用紙ごとに大きくできる（端末ごとに保存）
  - 文字は1行のまま入る大きさを探し、8ptを下回るときは確認文言を2行に折り返す
  - 印刷がずれるときは「位置調整」で mm 単位に補正（端末ごとに保存）
- 印刷時の設定：用紙A4・倍率100%（実際のサイズ）・余白なし。パソコンの Chrome がいちばん正確です

## 注意
- GAS を更新したら「デプロイを管理」→ 鉛筆 → バージョン「新バージョン」で更新すると URL が変わりません
- 再デプロイ後に「通信に失敗」と出たら、アクセスできるユーザーが「全員」のままか確認してください
- 「未送信」が残っている間は、その端末のブラウザのサイトデータを消さないでください
